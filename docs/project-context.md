# Tennis Survivor Project Context

## 项目定位

`tennis_survivor` 是一个面向网球签表幸存者玩家的静态网站。网站虽然技术上很轻量，但服务真实用户，每天可能有约 100 名左右用户访问，用来查看实时选人、即时积分、积分构成、每日航班、历史惨案和用户偏好。

核心目标不是做一个复杂产品，而是把用户每天真实需要的信息稳定、清楚、及时地呈现出来。

## 当前技术栈

- 前端：单文件 `index.html`
- 样式：内联 CSS
- 交互：Vanilla JavaScript
- 数据：静态 JSON 文件，位于 `data/`
- 数据生成：Python 脚本，位于 `scripts/`
- 部署：GitHub Pages
- 自动更新：GitHub Actions

## 主要页面模块

- ATP 实时选人
- WTA 实时选人
- ATP 积分构成
- WTA 积分构成
- ATP 用户偏好
- WTA 用户偏好
- 历史上的惨案 ATP
- 历史上的惨案 WTA
- 每日航班
- 每日运势

## 默认维护原则

1. 新功能先做设计，不直接写代码。
2. 用户确认设计后再编码。
3. 编码后必须本地预览和测试。
4. 用户确认本地预览后再发布 GitHub。
5. 每次发布都更新 `CHANGELOG.md`。
6. 重要数据规则必须加测试。
7. 不记录具体用户的敏感行为，不上传用户身份级埋点。
8. 优先保持现有静态站架构，只有确实需要写入数据时再引入后端能力。
9. 对话中出现值得长期保留的决策、规则、待办、验证结果或交接信息时，及时更新仓库内合适的 Markdown 文档；临时探索和闲聊不必记录。

## 新功能设计模板

当用户提出“我要增加一个新功能”时，先输出：

1. 功能设计
2. UI 改动
3. 需要修改的文件
4. 数据结构变化
5. 状态管理变化
6. 潜在风险
7. 实现步骤

用户确认后再开始编码。
